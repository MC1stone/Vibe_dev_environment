{% trans "Wie funktioniert federatedes Lernen hier?" %}

{% blocktrans %}Ihre Messdaten verlassen niemals Ihren Rechner. Stattdessen wird ein Kalibriermodell auf Ihren Daten trainiert und nur die Modellparameter (nicht die Spektren!) an die aggregierende Instanz uebermittelt. Dort werden die Parameter aller Teilnehmer zu einem gemeinsamen Modell verschmolzen. Das gemeinsame Modell profitiert von der Vielfalt aller Teilnehmer, ohne dass irgendjemand fremde Rohdaten sieht.{% endblocktrans %}

{% trans "Lernmodus" %}

standalone {% blocktrans %}Default. Alles laeuft nur auf diesem Rechner - keine Verbindung zu anderen Teilnehmern. Sicherste Option, kein Datenaustausch jeglicher Art.{% endblocktrans %}
client {% blocktrans %}Dieser Rechner traegt seine Modellparameter zu einer externen Runde bei. Es verlassen nur Parameter diesen Rechner - aber eben doch Datenfragmente (die Parameter).{% endblocktrans %}
server {% blocktrans %}Dieser Rechner sammelt die Parameter aller Clients und verschmilst sie zum gemeinsamen Modell. Sie sehen die Parameter aller Teilnehmer - vertrauenswuerdige Position im Labor verbietet sich.{% endblocktrans %}

{% trans "Aggregationsstrategie" %}

FedAvg {% blocktrans %}Default. Durchschnitt aller Client-Modelle. Einfach, robust, gut als Ausgangspunkt - bei sehr unterschiedlichen Sensoren kann ein einzelner Teilnehmer das gemeinsame Modell verzerren.{% endblocktrans %}
FedProx {% blocktrans %}FedAvg mit Stabilitaetsfaktor: Teilnehmer mit wenigen Messungen driften nicht ab. Sinnvoll, wenn die Teilnehmer unterschiedliche Datenmengen beisteuern.{% endblocktrans %}
FedAdam / FedYogi {% blocktrans %}Adaptive Optimierung: schnellere Konvergenz bei vielen Runden, aber mehr Hyperparameter, die korrekt gewaehlt werden muessen - eher fuers Labor-Feintuning.{% endblocktrans %}
FedSGD {% blocktrans %}Gradienten-Mittelung pro Runde statt fertiger Modelle - exakt, aber kommunikationsintensiver.{% endblocktrans %}

{% trans "Privacy-Stufen" %}

{% blocktrans %}Auswirkung: Keine Daten (auch keine Parameter) verlassen diesen Rechner. Die Federated-Logik laeuft lokal im Simulator. Diese Stufe ist der Default und die einzige Stufe ohne Einwilligungsbedarf.{% endblocktrans %}

{% blocktrans %}Auswirkung: Parameter werden vor der Uebertragung mit Rauschen versehen, damit sich aus ihnen keine einzelnen Messungen rekonstruieren lassen. Datenschutzbudget (epsilon, delta) wird ueber Runden gefuehrt und begrenzt. Preis: das gemeinsame Modell wird etwas ungenauer - je kleiner epsilon, desto staerker das Rauschen und desto groesser der Genauigkeitsverlust.{% endblocktrans %}

{% blocktrans %}Auswirkung: Die Parameter aller Clients werden verschluesselt aggregiert: der Server kann nur die Summe aller Updates sehen, nie die eines einzelnen Teilnehmers. Vertraulichkeit steigt, Berechnungsaufwand ebenfalls; verfuegbar nur mit dem flwr-Runtime (Status unten zeigt ehrlich an, ob aktiv).{% endblocktrans %}

{% blocktrans %}Auswirkung: Hoechste Vertraulichkeit: die Aggregation rechnet direkt auf verschluesselten Parametern, der Server sieht nie Klartext. Preis: deutlich mehr Rechenzeit und Speicher pro Runde - nur fuer hochsensible Messungen.{% endblocktrans %}

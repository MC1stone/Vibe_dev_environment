Getting Started

Welcome to the NIR_Mistral DeveloperAgent Framework! This guide will help you get started with using the framework for NIR spectroscopy analysis.

Prerequisites

  • Python 3.8+
  • Django 4.2+
  • PostgreSQL or SQLite
  • Modern web browser

Quick Start

  1. Install the framework using the installation guide
  2. Set up your database and run migrations
  3. Create a superuser account
  4. Start the development server
  5. Access the web interface at http://localhost:8000
Tip: Check out the Framework Overview to understand the architecture.

Installation

Method 1: Manual Installation

# Clone the repository
git clone https://github.com/martin/Development/vsCode_Environment/NIR_Mistral.git
cd NIR_Mistral

# Create virtual environment
python -m venv venv
source venv/bin/activate  # On Windows: venv\Scripts\activate

# Install dependencies
pip install -r requirements.txt

# Run migrations
cd django_project
python manage.py migrate

# Create superuser
python manage.py createsuperuser

# Start development server
python manage.py runserver

Method 2: Docker Installation

# Build and run with Docker
docker-compose up -d

# Access the application at http://localhost:8000

Method 3: Ansible Deployment (Recommended for Production)

For production deployments, especially on Venty Stick devices, use the Ansible playbooks:

# Navigate to ansible directory
cd ansible

# Install Ansible requirements
ansible-galaxy install -r galaxy_requirements.yml

# Run the setup playbook
ansible-playbook -i inventory/hosts.yml playbooks/setup_venty_stick.yml

Framework Overview

Architecture

The NIR_Mistral DeveloperAgent Framework is built on a modular architecture with the following components:

Core Framework
  • Agent System: Manages and executes analysis agents
  • Data Processing: Handles NIR spectroscopy data
  • Job Management: Tracks analysis jobs and results
  • Quality Control: Validates data quality
Web Interface
  • Dashboard: Overview of system status and recent activity
  • Spectra Management: Upload, view, and manage NIR spectra
  • Analysis: Run analysis using framework agents
  • Jobs: Monitor and manage analysis jobs
  • Agents: View and manage available agents

Data Flow

The typical data flow in the framework is:

  1. Data Upload: Users upload NIR spectroscopy data in various formats
  2. Data Processing: Data is parsed and stored in the database
  3. Quality Control: Data quality is validated automatically
  4. Analysis: Users select agents and parameters for analysis
  5. Job Execution: Analysis jobs are executed by the framework
  6. Results Storage: Results are stored and made available for viewing

Creating Custom Agents

You can create custom agents by following these steps:

  1. Create a new Python file in the agents/ directory
  2. Implement the BaseAgent interface
  3. Define your analysis methods
  4. Register your agent with the framework
Example Agent Structure
from dev_framework.agents import BaseAgent

class MyCustomAgent(BaseAgent):
    def __init__(self):
        super().__init__(
            name="MyCustomAgent",
            version="1.0.0",
            description="My custom analysis agent"
        )
    
    def analyze(self, spectrum, parameters=None):
        # Your analysis logic here
        result = {
            'mean_absorbance': spectrum.get_mean_absorbance(),
            'peaks': spectrum.find_peaks()
        }
        return result

Spectra Management

Supported File Formats

TXT Files

Plain text files with wavelength and absorbance columns. Supports various delimiters (comma, tab, space).

CSV Files

Comma-separated values format. First row should contain headers (wavelength, value).

JSON Files

JSON format with wavelength and value arrays. Supports additional metadata.

Uploading Spectra

  1. Navigate to the Spectra page
  2. Click the Upload Spectrum button
  3. Fill in the spectrum information (name, ID, type)

  5. Optionally add metadata and description
  6. Click Upload to save the spectrum

Spectrum Metadata

Each spectrum can include metadata such as:

  • Sample information (name, ID, type)
  • Instrument details

  • Custom properties

Analysis

Analysis Types

Peak Detection

Identifies and analyzes spectral peaks using various algorithms (local maxima, derivatives).

Parameters:
  • Method: local_maxima, first_derivative, second_derivative
  • Threshold: Minimum peak height
  • Minimum distance: Minimum distance between peaks
Quality Control

Validates data quality and integrity with comprehensive checks.

Checks:
  • Wavelength range validation
  • Resolution verification
  • Data integrity (NaN/Inf detection)
  • Signal-to-noise ratio
Statistical Analysis

Computes statistical metrics for the spectrum.

Metrics:
  • Mean, median, standard deviation
  • Minimum, maximum, range
  • Skewness, kurtosis
  • Derivative analysis
Comparative Analysis

Compares multiple spectra using various methods.

Methods:
  • Overlay plot
  • Difference spectrum
  • Correlation analysis
  • Statistical comparison

Running an Analysis

  1. Navigate to the Analysis page
  2. Select an analysis type from the available methods
  3. Choose a spectrum to analyze
  4. Select an agent to perform the analysis
  5. Configure analysis-specific parameters
  6. Click Start Analysis to begin
  7. Monitor progress in the Active Jobs section
  8. View results when the analysis completes

Troubleshooting

Common Issues

Solution: Check your database connection settings in settings.py.

  • Verify database server is running
  • Check connection credentials
  • Test connection manually using database client

Solution: Check file format and size limits.

  • Ensure file is in supported format (TXT, CSV, JSON)
  • Check file size doesn't exceed maximum limit
  • Verify file contains required columns (wavelength, value)

Solution: Check worker processes and queue system.

  • Verify Celery worker is running
  • Check Redis server connection
  • Restart worker processes

Error Codes

Code Description Solution
400 Bad Request Check request parameters and format
401 Unauthorized Verify authentication token
403 Forbidden Check user permissions
404 Not Found Verify endpoint URL
500 Internal Server Error Check server logs for details

Federated Learning

Overview

Federated Learning enables collaborative model training across multiple devices and locations without sharing raw data. This preserves privacy while allowing the development of more robust and accurate models.

Privacy First: Your data remains on your device. Only model updates are shared, never the raw data.

How Federated Learning Works

  1. Local Training: Each participant trains a model on their local data
  2. Model Updates: Only model parameters (not data) are shared with the central server
  3. Aggregation: The central server aggregates updates from multiple participants
  4. Improved Model: An enhanced global model is created and distributed back to participants
  5. Iterative Process: The cycle continues, improving the model with each round

Benefits of Federated Learning

Data Privacy

Raw data never leaves your device. Only model updates are shared, ensuring complete privacy.

Collaborative Improvement

Benefit from the collective knowledge of the entire network while maintaining data privacy.

Scalable Learning

The model improves as more participants join, scaling with the network size.

Distributed Computing

Leverage computing resources across multiple devices for faster model training.

Privacy Controls

The framework provides granular privacy controls for federated learning:

Privacy Level Description Data Sharing Model Sharing
Local Only Data stays completely local No No
Private Federated Enhanced privacy with federated learning No Yes
Public Federated Standard federated learning participation No Yes

Contributing to Federated Learning

To contribute your data to federated learning:

  1. Navigate to the Settings page
  2. Go to the Federated Learning section
  3. Review the privacy policy and terms of service
  4. Select your preferred privacy level
  5. Enable federated learning participation
  6. Provide explicit consent for data contribution
  7. Your data will be used for local training, and only model updates will be shared
Important: You must provide explicit consent before participating in federated learning. You can withdraw consent at any time.

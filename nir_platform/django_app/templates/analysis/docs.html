{% if section == "Getting Started" %}
Installation

The NIR Intelligence Platform can be installed using Docker for easy deployment. 

# Clone the repository
git clone https://github.com/MC1stone/Vibe_dev_environment
cd Vibe_dev_environment/nir_platform

# Start Docker containers
docker-compose -f docker/docker-compose.yml up -d

# Access the platform
# Django: http://localhost:8000
# n8n: http://localhost:5678
# Ollama: http://localhost:11434
Quick Start
  1. Upload your spectral data file
  2. Wait for the AI agents to analyze it
  3. Review the comprehensive report
  4. Download results or share with federated learning
{% elif section == "Uploading Data" %}
Supported File Formats
  • CSV: Comma-separated values with wavelength and intensity columns
  • TXT: Tab or space-separated values
  • Excel: XLSX or XLS files with spectral data
  • JSON: JSON format with wavelengths and intensities arrays
  • SPC/JDX: Standard spectroscopy file formats
  • ZIP: Archive containing multiple spectral data files
File Requirements
  • Maximum file size: 100MB
  • Must contain wavelength and intensity data
  • Wavelengths should be in ascending order
  • Intensities should be numeric values
{% elif section == "Spectral Analysis" %}
Analysis Process

The spectral analysis process includes the following steps:

  1. Data Loading: Parse spectral data from the uploaded file
  2. Spectrometer Detection: Automatically detect spectrometer type
  3. Wavelength Calibration: Correct wavelength measurements using known emission lines
  4. Baseline Correction: Remove baseline drift and offset
  5. Noise Reduction: Apply Savitzky-Golay filter for noise reduction
  6. Smoothing: Apply moving average smoothing
  7. Peak Detection: Identify peaks and spectral features
  8. Issue Detection: Detect potential spectrometer issues
  9. Quality Assessment: Calculate overall data quality score
Output

The analysis produces:

  • Processed spectral data
  • Analysis metrics (peaks, statistics, quality scores)
  • Detected issues and warnings
  • Calibration recommendations
  • Quality assessment
{% elif section == "Metadata Quality" %}
Standards

Metadata is evaluated against the following international standards:

  • ISO 19115: Geographic Information - Metadata
  • ASTM E131: Molecular Spectroscopy Terminology
  • ASTM E1421: Computerized IR Spectroscopy Data Fields
  • NIR-Specific: Standards specific to Near-Infrared spectroscopy
  • Open Science: Standards for open science data sharing
  • Federated Learning: Standards for federated learning data sharing
Scoring

Each standard has required and optional fields. The metadata quality score is calculated based on:

  • Presence of required fields (70% weight)
  • Presence of optional fields (30% weight)
  • Field validation (correct data types, formats, etc.)
Grading
Score Range Grade Description
95-100 A+ Excellent - All required fields present and valid
90-94 A Very Good - Minor improvements possible
85-89 A- Good - Some optional fields missing
80-84 B+ Above Average - Several optional fields missing
70-79 B-C Average - Some required fields missing
60-69 D+ Below Average - Multiple required fields missing
0-59 F Poor - Many required fields missing or invalid
{% elif section == "Calibration" %}
Calibration Types

The platform supports several types of calibration:

  • Wavelength Calibration: Corrects wavelength measurements using known emission lines
  • Intensity Calibration: Normalizes intensity measurements using white and dark references
  • Drift Compensation: Compensates for temperature and time-related drift
Calibration Methods

Different calibration methods are available:

  • Linear: Simple linear correction (y = mx + b)
  • Polynomial: Higher-order polynomial fitting for non-linear corrections
  • Exponential: For exponential relationships
Reference Materials

Supported reference materials for intensity calibration:

  • Spectralon: High-reflectance white reference standard (99% reflectance)
  • Infragold: Gold-coated diffuse reflectance standard (95% reflectance)
  • Ceramic Tile: Ceramic white reference tile (97% reflectance)
  • NIST SRM 2065: NIST traceable Spectralon reflectance standard

{% elif section == "Federated Learning" %}
What is Federated Learning?

Federated learning is a collaborative approach to machine learning where multiple participants train models on their local data without sharing the data itself. This allows for:

  • Improved models trained on diverse data from many sources
  • Privacy preservation - your data never leaves your control
  • Decentralized model training
  • Continuous improvement of shared models
How It Works
  1. You analyze your spectral data locally
  2. You choose to share your results with the federated learning network
  3. Your data is anonymized (if you choose) and only model updates are shared
  4. The central model is updated with contributions from all participants
  5. You receive an improved model for future analyses
Privacy & Security

Your privacy is our priority:

  • Data Control: You always control your data - sharing is opt-in
  • Anonymization: Data can be anonymized before sharing
  • Local Processing: All analysis happens locally by default
  • Transparent: You can see exactly what is being shared
  • Reversible: You can revoke consent at any time
Note: Federated learning is currently in development. This feature will be available in future versions.
{% elif section == "DIY Spectrometer Guide" %}
Introduction

Building your own Near-Infrared (NIR) spectrometer is an exciting and educational project that allows you to perform spectral analysis at a fraction of the cost of professional equipment. This guide will walk you through the process of building a DIY NIR spectrometer.

Supported DIY Spectrometers
Name Components Wavelength Range Resolution Cost Difficulty
Raspberry Pi + AS7262 Raspberry Pi, AS7262 sensor, White LED 650-1100 nm ~10 nm ~$100 Medium
Arduino + TCS34725 Arduino Uno, TCS34725 sensor, White LED 700-1000 nm ~15 nm ~$30 Easy
Components

Here are the components you'll need for each DIY spectrometer:

Raspberry Pi + AS7262:
  • Raspberry Pi (any model with I2C)
  • AS7262 6-channel NIR sensor
  • White LED for reference
  • Diffuser material (optional)
  • Sample holder
  • Breadboard and jumper wires
  • Power supply
Arduino + TCS34725:
  • Arduino Uno or compatible
  • TCS34725 RGB color sensor
  • White LED for reference
  • Breadboard and jumper wires
  • Power supply
Assembly Instructions

Detailed assembly instructions are provided in the platform's DIY guide section. The process typically involves:

  1. Connecting the sensor to the microcontroller via I2C
  2. Adding the white LED for intensity reference
  3. Setting up the sample holder
  4. Installing the necessary software
  5. Calibrating the spectrometer
Calibration

Calibration is crucial for accurate measurements. The platform provides:

  • Step-by-step calibration procedures
  • Known emission lines for wavelength calibration
  • Reference materials for intensity calibration
  • Automated calibration verification
Limitations

While DIY spectrometers are great for education and basic analysis, they have some limitations:

  • Lower Resolution: DIY sensors have lower spectral resolution than professional equipment
  • Limited Range: Coverage is typically limited to specific wavelength ranges
  • Lower Sensitivity: May require longer integration times or multiple scans
  • Temperature Sensitivity: More sensitive to temperature changes
  • Calibration Frequency: Requires more frequent calibration
Tip: Start with the Arduino + TCS34725 for a low-cost introduction, then upgrade to Raspberry Pi + AS7262 for better performance.
{% elif section == "API Reference" %}
REST API

The platform provides a REST API for programmatic access to analysis functionality.

Endpoints:
Endpoint Method Description
/api/analyze/ POST Perform spectral analysis
/api/chat/ POST Chat with AI agents
Request Examples:
Spectral Analysis: 
POST /api/analyze/
Content-Type: application/json

{
    "wavelengths": [700, 701, 702, ...],
    "intensities": [100, 105, 110, ...],
    "metadata": {
        "spectrometer_type": "ocean_optics",
        "sample_type": "solid",
        "date": "2024-01-15"
    }
}
Chat: 
POST /api/chat/
Content-Type: application/json

{
    "message": "What peaks are in my spectrum?",
    "context": {
        "analysis_id": "uuid"
    }
}
WebSocket API

Real-time communication with the MCP server and AI agents.

Events:
  • agent_message: Messages from AI agents
  • analysis_progress: Progress updates during analysis
  • calibration_complete: Notification when calibration is done
Connection:
// Connect to MCP server
const socket = new WebSocket('ws://localhost:8000/ws');

// Send message
socket.send(JSON.stringify({
    type: 'agent_message',
    agent_id: 'spectral_analysis_agent',
    content: 'Analyze this spectrum...'
}));

// Receive messages
socket.onmessage = (event) => {
    const message = JSON.parse(event.data);
    console.log('Received:', message);
};
Integration Examples
Python:
import requests
import json

# Spectral analysis
response = requests.post(
    'http://localhost:8000/api/analyze/',
    json={
        'wavelengths': [700, 701, 702],
        'intensities': [100, 105, 110]
    }
)

results = response.json()
print(results)
JavaScript:
fetch('http://localhost:8000/api/analyze/', {
    method: 'POST',
    headers: {
        'Content-Type': 'application/json'
    },
    body: JSON.stringify({
        wavelengths: [700, 701, 702],
        intensities: [100, 105, 110]
    })
})
.then(response => response.json())
.then(data => console.log(data));
